# PR validation and security maintenance

Every PR to main must pass the aggregate `CI` check, comprising mandatory application, compatibility and security jobs. Main protection additionally requires a current approving code-owner review and resolved conversations. Administrators are included. Workflow, source, dependency, test and security-policy changes require owner review; a PR author cannot supply their own required approval.

Validation has read-only contents permissions, credential-free checkout, no deployment environment or secret references, and immutable Action commits. The parsed workflow policy and its mutation tests reject privileged triggers, token escalation, secret access (including bracket syntax), conditional validation, mutable Actions and suppressed failures. The aggregate check fails if any validation job fails or is skipped.

The security job scans Git history with redacted Gitleaks, runs Actionlint, and installs Semgrep 1.183.0 plus PyYAML from a transitive hash-locked requirements file. Forty local rules (39 official Semgrep rules plus the project request-to-SQL taint rule) run with findings and parse errors blocking CI. Vendored upstream rules are bound to their recorded commit and checked SHA-256 inventory. Regression fixtures prove the real analyzer rejects SQL injection and eval. To update tooling, edit `.github/security-requirements.in`, generate hashes with `uv pip compile --generate-hashes --python-version 3.12`, and review the resulting lock. Updates to upstream rules require refreshed provenance and review.

SAST covers shipped source: application/API, SDK, React embed/copy modules, and guard/migration Rust sources as applicable. Test fixtures, diagnostic/asset-generation scripts, generated SDK ABI files, build outputs and vendored upstream artifacts are excluded from application SAST. Scripts remain covered by owner review, secret scanning and the appropriate existing type/workflow checks. Semgrep cannot parse the SDK's type-namespace barrel syntax: `scripts/scan-security.py` first proves that the excluded `sdk/src/index.ts`, when present, contains only local re-exports. Any executable addition or external export fails closed. No SDK runtime source or archive is rewritten for this workaround.

A weekly Monday audit reruns the complete workflow on main. Deployment runs only after CI on trusted main push/manual dispatch, with the protected production environment. Scheduled and PR runs cannot deploy. Frozen dependency installs, full JS dependency audits at high severity (including development/build dependencies), and npm/Cargo and security-tooling pip Dependabot updates keep the build supply chain under review. A passing pipeline is evidence from these checks; financial/authentication changes still need qualified human security review and existing release acceptance.

## Rust advisories and real-WASM invariants

The patched major cannot be substituted compatibly into the pinned SDK. Every run proves neither crypto-bigint nor soroban-env-host appears in either deployed contract's normal wasm32v1-none dependency graph. Fixtures use mocked authorization and public verification inputs, with no production secret scalar operations. The exception expires on 2027-01-01 and fails closed: any other advisory/version, guest-graph exposure, expiry or removal of the original finding requires resolution/review. No unrestricted cargo-audit ignore option is used. RustSec's unmaintained paste 1.0.15 notice remains visible as upstream maintenance debt; unsoundness warnings fail.

Clippy runs on every workspace target with warnings denied. Narrow allowances preserve the existing event ABI and imported upstream ABI argument counts. Deployed guard and migration WASM hashes remain verified. Nineteen compiled-WASM tests include a deterministic 18-case share/route sweep across rounding boundaries that measures real output, rejects minimum output + 1 with a full ledger rollback, rejects neighboring-share authority, accepts the exact bound, reconciles balances and rejects replay without ledger changes. Existing migration remainder/refund and destination rollback tests remain mandatory.
